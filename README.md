# Telegram Weather Bot

Погода в Telegram: по названию города возвращает температуру, ощущаемую температуру, ветер, влажность и прогноз на 7 дней. Город по умолчанию сохраняется; подписчикам бот отправляет погоду ежедневно в 9:00.

Данные — **Open-Meteo**: бесплатный публичный API без ключа и без лимитов для личного использования. Геокодинг городов — через их же API.

## Команды

| Команда | Назначение |
|---|---|
| `/weather Москва` | текущая погода |
| `/forecast Москва` | прогноз на 7 дней |
| `/city Москва` | сохранить город по умолчанию (далее достаточно `/weather`) |
| `/daily` | подписка на ежедневную рассылку погоды |

## Обоснование выбора Open-Meteo

Погодные API с ключами (OpenWeather и аналоги) требуют регистрации, управления лимитами и хранения секретов в коде. Open-Meteo работает без ключа и регистрации; данные открытые (источник — метеослужбы и NOAA). Для учебного проекта и демонстрации такое решение оптимально.

## Принцип работы

- геокодер определяет координаты по названию города;
- прогноз кэшируется на 30 минут (`TTL-кэш` из `utils.py`) для снижения нагрузки на API;
- APScheduler каждое утро в 9:00 рассылает погоду подписчикам (город каждого — из его настроек);
- демо-режим (`WEATHER_DEMO_MODE=1`) формирует синтетические данные с джиттером для запуска без сети;
- парсинг ответа вынесен в чистые функции `_parse_current` / `_parse_forecast`, что позволяет покрывать их unit-тестами без моков HTTP.

## Запуск

```bash
python -m venv .venv
pip install -r requirements.txt
export WEATHER_BOT_TOKEN=123456:ABC...   # токен от @BotFather
export WEATHER_DEMO_MODE=1               # 0 — реальный Open-Meteo
python bot.py
```

На Windows — `run_bot7.cmd` (токен из корневого `.env`).

## Структура проекта

```
bot.py          — команды, рассылка, форматирование сообщений
weather_api.py  — клиент Open-Meteo: геокодинг, текущая погода, прогноз
db.py           — aiosqlite: город по умолчанию, подписки на рассылку
utils.py        — TTL-кэш и retry с джиттером на чистом stdlib
middlewares.py  — троттлинг и логирование
config.py       — настройки из переменных окружения
tests/          — 7 тестов (парсинг текущей погоды, прогноза, кэш, подписки)
```

## Планы развития

- оповещение о неблагоприятных условиях (например, об осадках) по расписанию;
- погода для нескольких городов в одном сообщении;
- настройка единиц измерения скорости ветра (в настоящее время км/ч; часть пользователей предпочитает м/с).

## Тесты

`pytest tests/ -q` — 7 тестов. GitHub Actions прогоняет их при каждом push.
